## 2. Audit findings (verified 2026-10-30, read-only)

1. **The declared logo URL is dead.** The ONLY logo declaration in the entire estate is in the
   best entity graph, as a bare string with no dimensions:
   `"logo": "https://theflatratemovers.com/assets/logo.png"` — and `/assets/logo.png` does not
   exist. Verified live: `GET https://theflatratemovers.com/assets/logo.png` → **404**; no such
   file in `public/assets/`. The real logo is `assets/img-01-9c77693ba66b.png` (1024×1024).
   The dead declaration appears in exactly 3 copies:
   - `public/best-json-entity-graph.json` (live)
   - machine repo `data/best-json-entity-graph.json`
   - ai repo `data/best-json-entity-graph-full.json` (read back via connector, confirmed)
   An AI surface or knowledge panel following the declared logo gets a 404 — the direct cause
   class for the broken/mis-sized logo in Henry's screenshot.
2. **No logo anywhere else.** The Organization node in the index.html head graph, in all 162
   per-page JSONs, and in `entity-graph.json` (34-node) carries NO `logo` property at all
   (full-tree scan: only the best graph has the key). No width/height declared anywhere.
3. **Favicon is an empty placeholder.** The shell head carries exactly one icon tag:
   `<link rel="icon" href="data:,">`. No favicon.ico, no PNG icons, no apple-touch-icon, no
   manifest link anywhere. The middleware contains no icon handling — it rewrites the head by
   anchored replacement, so the placeholder passes straight through to every served page.
   (`<meta name="theme-color" content="#0c2340">` already exists and is correct — keep it.)
4. **On-site header/footer logo sizing is correct.** `.logo-img` = 58×58 (50×50 small screens),
   `object-fit:contain`, `aspect-ratio:1/1`, white background — square mark in a square slot, no
   crop. `.footer-logo img` = contain, 1/1. Hero logo renders 200px wide, height auto.
5. **One real on-site crop:** two page figures use the square logo PNG in `.wideph` slots —
   `.wideph{object-fit:cover; aspect-ratio:21/9}` (16/10 in a second rule). `cover` on a wide
   slot crops the square logo top and bottom — the same cropped look as the screenshot. The two
   instances: `<img class="wideph" src="/assets/img-01-9c77693ba66b.png" …>` in index.html.
6. **og:image / twitter:image** point to `assets/img-02-0b80bbb82653.jpg` (a photo) — a normal
   social-share choice, not the logo; no change.
7. **Signed-index precedent for assets:** ZERO image/asset files are distributions (P2 scope =
   per-page JSONs, shell, code, datasets, graphs). The favicon PNGs/ICO therefore do NOT become
   distributions; `site.webmanifest` follows the utility-root-file precedent (the Yandex
   verification HTML is not a distribution either). This batch changes digests, not the
   distribution count.

## 3. The fix (patch plan — apply on a clean tree)

```html
<link rel="icon" href="/favicon.ico" sizes="any">

<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png">
<link rel="manifest" href="/site.webmanifest">
```

### 3c. Logo declaration — graphs (3 copies listed in §2.1)
Replace `"logo": "https://theflatratemovers.com/assets/logo.png",` with the ImageObject form
(match each file's local indentation):
```json

  "@type": "ImageObject",
  "url": "https://theflatratemovers.com/assets/img-01-9c77693ba66b.png",
  "width": 1024,
  "height": 1024
},
```

repo's `tools/gen-head-data.js` after the source change (generator header in head-data.js
